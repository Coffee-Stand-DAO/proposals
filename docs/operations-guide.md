# NFT販売運用手順書

## 概要

本ドキュメントは、Gnosis SafeでのOpenSeaログイン時のガス代問題を解決するための運用手順を定義します。

## 運用フロー

### 1. 運用担当者（Operator Wallet）

コアメンバー1人が運用担当者として、以下の責任を負います：

- OpenSeaでのNFT販売・購入の実行
- 定期的な資金移転の実施
- 取引記録の報告

### 2. 資金移転フロー

```
OpenSea販売収益 → Operator Wallet → Gnosis Safe
```

#### 手順

1. **OpenSeaでの販売**
   - Operator WalletでOpenSeaにログイン
   - NFTを販売
   - 収益はOperator Walletに入金

2. **資金移転**
   - 週次または月次で決定したタイミングで資金をGnosis Safeへ移転
   - 移転スクリプトを使用

3. **報告**
   - 移転完了後、コアメンバーに報告

### 3. スクリプトの使用方法

#### 準備

```bash
# 必要なパッケージをインストール
npm install

# .envファイルを作成
cp .env.example .env
nano .env

# 環境変数を設定
OPERATOR_PRIVATE_KEY=your_private_key_here
GNOSIS_SAFE_ADDRESS=0x...
RPC_URL=https://polygon-rpc.com
```

#### 実行

```bash
# 全額移転
npm run transfer:funds

# 特定金額移転
node scripts/transfer-funds.js --amount 100

# トークン指定（ERC20）
node scripts/transfer-funds.js --token 0x1234...abcd

# ドライラン（実行せずシミュレーションのみ）
npm run transfer:funds:dry-run
```

## ガバナンスルール

### 1. 運用担当者の選定

- コアメンバーから投票で選定
- 任期は3ヶ月、再選可能
- 不適格と判断された場合は解任可能

### 2. 報告義務

- 取引の都度報告（Slack/Discord等）
- 月次報告：取引総額、手数料、純利益
- 四半期ごとの監査

### 3. 資金移転頻度

- 基本：週次（毎週月曜日）
- 大口取引後：即時移転
- 状況に応じて柔軟に調整

### 4. 緊急時の対応

- 異常が検知された場合、即時報告
- Gnosis Safeのマルチシグで対応を決定
- 必要に応じて運用担当者を変更

## リスク管理

### 1. 運用担当者リスク

- **対策**:
  - 小額からの運用開始
  - 複数人の運用担当者ローテーション
  - 透明性の確保（トランザクションの公開）

### 2. セキュリティリスク

- **対策**:
  - プライベートキーの適切な管理（ハードウェアウォレット推奨）
  - 2FAの有効化
  - 定期的なアドレス監視

### 3. 合法性・コンプライアンス

- **対策**:
  - すべての取引記録を保持
  - 税務申告用のデータ整理
  - 必要に応じて法務アドバイス

## 監査

- 四半期ごとに独立した監査を実施
- トランザクション履歴の公開
- 不正が発覚した場合、即時対応と再発防止策の策定
